# 小程序切图与视觉资源交付规范

适用范围：微信小程序会员端 v1 的静态视觉资源（图标、插画、Banner、照片）。
本规范共 **7 个部分**，与交付检查清单、检查脚本配套使用。所有示例数据、文件名均为虚构。

## 1. Naming（文件命名）

| 规则 | 说明 |
|---|---|
| 字符集 | 仅小写字母 `a-z`、数字 `0-9`、连字符 `-`；禁止大写、下划线、空格、中文 |
| 结构 | `<module>-<name>[@2x\|@3x].<ext>`，其中 `<module>` 为模块前缀 |
| 模块前缀 | `home` / `academy` / `pod` / `sales` / `ops` / `common` |
| 倍率后缀 | 仅 `@2x`、`@3x`，放在扩展名之前；1x 资源不写后缀 |
| 扩展名 | `.svg` / `.jpg` / `.png`（与第 3 节格式选择一致） |
| 机器校验正则 | `^[a-z][a-z0-9]*-[a-z0-9-]+(@[23]x)?\.(svg\|jpg\|png)$` |

正例：`home-icon-arrow@2x.svg`、`ops-illust-welcome.svg`、`common-banner-lobby.jpg`。
反例：`Icon_Home.png`（大写 + 下划线）、`standalone.png`（缺模块前缀与连字符）。

## 2. Table of Contents（目录结构）

```
assets/
  icons/        # 图标：SVG 或 iconfont 产物
  images/       # 插画、Banner、照片
```

- `assets/icons` 只放图标；`assets/images` 放插画与位图，两类不得混放。
- 倍率变体与 1x 版本放在同一目录，靠 `@2x` / `@3x` 后缀区分，不另建 `2x/` 子目录。
- 文件名中的语义前缀决定体积档位：`icon-` → 图标上限，`illust-` → 插画上限，
  `banner-` → Banner 上限；检查脚本据此判定。
- 临时稿、导出中间文件不得进入交付目录。

## 3. Scale and Format（倍率与格式）

| 资源类型 | 倍率 | 格式 | 说明 |
|---|---|---|---|
| 图标 | 2x / 3x | SVG 优先，或 iconfont | 矢量，避免位图放大模糊 |
| 插画 | 2x / 3x | SVG 优先 | 复杂渐变无法矢量时转 JPG（质量 80） |
| 照片 | 2x / 3x | JPG，质量 80 | 不使用 PNG 存照片 |
| Banner | 2x / 3x | JPG 质量 80 或 SVG | 含文字时优先保留可编辑图层说明 |

- 同一资源必须同时提供 `@2x` 与 `@3x`，或声明使用 SVG 单份适配。
- PNG 仅用于必须保留透明通道的位图，且需在清单中注明原因。
- 导出时不做二次压缩，避免质量参数与规范不一致。

## 4. Volume（单文件体积上限）

| 类别 | 命名前缀 | 上限 |
|---|---|---|
| 图标 | `icon-` | ≤ 4 KB |
| 插画 | `illust-` | ≤ 30 KB |
| Banner | `banner-` | ≤ 120 KB |
| 其他位图 | 其余 | ≤ 120 KB |

- 上限按**单文件字节数**判定，检查脚本以 `fs.statSync().size` 为准。
- 超限处理顺序：先精简路径与去除元数据 → 再降质量参数 → 仍超限则拆分资源或移入分包。
- 不得以改扩展名的方式规避体积检查。

## 5. Subcontracting（主包与分包放置）

- 主包总体积 **≤ 2 MB**，检查脚本之外的发布流程需复核主包实际体积。
- 大图（接近或超过 120 KB）优先放入分包；超出分包预算的转存**客户自有对象存储**，
  由客户云账号托管，资源地址通过配置读取。
- **不使用境外 CDN**；配置与密钥只从环境变量读取。
- 分包内的资源仍需遵守第 1 节命名与第 4 节体积规则；跨分包复用资源放 `common-` 前缀。
- 引用远程资源时必须提供加载失败占位，避免主包渲染阻塞。

## 6. Color Scheme（配色）

- 颜色**只引用设计变量**，例如 `var(--color-primary)` / 设计令牌表中的 token 名；
  禁止在 SVG、样式与切图中硬编码十六进制色值。
- 深色/浅色模式通过变量切换，不额外导出一套深色切图。
- 图标使用 `currentColor` 继承前景色；确需固定色的品牌标识需在清单登记例外原因。
- 新增色值必须先进入设计令牌表评审，再被资源引用。

## 7. Chart Markup（Figma 图标标注方法）

本节描述标注与交付约定，仅要求文字规范，**不要求交付 Figma 源文件或截图**。

- 每个图标在 Figma 中建立独立 Component，命名与第 1 节文件名一致（不含倍率后缀）。
- 在 Component 的描述字段标注：模块前缀、语义名、导出倍率、导出格式、网格尺寸
  （建议 24×24 / 48×48）、是否需要透明通道。
- 切图导出使用 Export 预设，预设名与文件名前缀一致；导出后按第 1 节重命名。
- 颜色以设计变量名为标注值；若使用 `currentColor`，在描述中写明。
- 标注示例（虚构）：`home-icon-arrow | module=home | export=@2x,@3x | format=svg | grid=24 | color=var(--color-icon) | alpha=keep`。
- 交付目录中的每个文件都应能追溯到一条标注记录；检查脚本负责校验文件名与体积，
  标注记录由交付清单人工逐项勾核。
